# service — 실제 로직을 처리하는 곳

프로젝트의 **핵심 두뇌**입니다. "무엇을 어떻게 처리할지"가 전부 여기에 들어갑니다.

## 하는 일

- 비즈니스 규칙 검증 (예: 종료일이 시작일보다 빠르면 거부)
- 여러 Repository·External을 조합해 결과 생성
- 트랜잭션 관리 (`@Transactional`)

## 예시 — 우리 프로젝트의 주요 로직

| Service | 하는 일 |
|---|---|
| `AuthService` | 이메일 중복 확인, 비밀번호 해시, 로그인 검증 |
| `EventService` | 조건에 맞는 문화행사 검색·필터링 |
| `PlanService` | **행사 시각을 고정**하고 주변 장소를 조합해 일정 생성 |
| `PlaceService` | 외부 API 결과를 공통 Place 형태로 변환·중복 제거 |

## 파일명 규칙
