# 02. 커밋 메시지 규칙

> 커밋 메시지는 **나중에 "언제 무엇을 왜 바꿨는지" 찾는 단서**입니다.
> `수정`, `ㅇㅇ`, `asdf` 같은 메시지는 몇 주 뒤 아무 도움이 되지 않습니다.

---

## 기본 형식

```
<타입>: <무엇을 했는지 한 줄 요약>
```

예시:

```
feat: 로그인 API 구현
fix: 지도 마커가 겹쳐 보이는 문제 수정
docs: README에 디렉토리 구조 추가
```

---

## 타입 목록

| 타입 | 언제 쓰나 | 예시 |
|---|---|---|
| `feat` | **새 기능** 추가 | `feat: 문화행사 검색 필터 추가` |
| `fix` | **버그** 수정 | `fix: 종료일이 시작일보다 빠를 때 오류 수정` |
| `docs` | **문서**만 수정 | `docs: API 명세 규칙 문서 작성` |
| `style` | 코드 **동작 변화 없는** 포맷·들여쓰기 | `style: 들여쓰기 정리` |
| `refactor` | 동작은 같고 **구조만** 개선 | `refactor: 일정 생성 로직 서비스로 분리` |
| `test` | **테스트 코드** 작성·수정 | `test: 회원가입 유효성 검사 테스트 추가` |
| `chore` | **설정·빌드·패키지** 등 잡무 | `chore: .gitignore에 .env 추가` |
| `design` | **UI/CSS** 변경 | `design: 메인 화면 카드 여백 조정` |

---

## 작성 요령

### ✅ 좋은 예

```
feat: 서울시 문화행사 API 연동
fix: 로그인 실패 시 에러 메시지가 안 뜨는 문제 수정
refactor: 중복된 날짜 검증 로직을 유틸로 분리
chore: Spring Boot 3.5로 버전 업
docs: 팀원용 깃허브 기초 가이드 추가
```

### ❌ 나쁜 예

| 메시지 | 문제점 |
|---|---|
| `수정` | 무엇을 수정했는지 없음 |
| `ㅇㅇ`, `asdf`, `1` | 의미 없음 |
| `최종` / `진짜최종` / `최종2` | 나중에 구분 불가 |
| `feat: 작업함` | 내용이 없음 |
| `여러가지 수정` | 커밋을 나눠야 할 신호 |

---

## 커밋 단위

**하나의 커밋 = 하나의 의미 있는 변경**

```
❌ 나쁨 : 로그인 + 회원가입 + 지도 + CSS 를 한 커밋에
✅ 좋음 : feat: 로그인 API 구현
          feat: 회원가입 API 구현
          design: 로그인 화면 여백 조정
```

> 💡 커밋을 잘게 나누면 문제가 생겼을 때 **어디서 깨졌는지** 찾기 쉽습니다.

---

## 조금 더 자세히 쓰고 싶을 때 (선택)

한 줄로 부족하면, 제목 아래 **빈 줄 하나**를 두고 본문을 씁니다.

```
feat: AI 일정 생성 기능 구현

- 선택한 문화행사 시간을 고정하고 앞뒤로 맛집·관광지 배치
- 좌표 간 직선거리로 방문 순서 정렬
- 후보가 부족하면 임의로 채우지 않고 안내 메시지 반환
```

터미널에서 여러 줄 커밋:

```bash
git commit          # -m 없이 실행 → 편집기가 열림
# i 눌러 입력 → Esc → :wq → Enter
```

---

## 이슈 번호 연결 (선택)

GitHub Issues를 사용한다면 메시지 끝에 번호를 적습니다.

```
feat: 즐겨찾기 등록/해제 구현 (#12)
```

`Closes #12` 라고 쓰면 PR이 병합될 때 해당 이슈가 자동으로 닫힙니다.

---

## 커밋 전 체크리스트

- [ ] `git status`로 **의도한 파일만** 담겼는지 확인했다
- [ ] `application.properties`, `.env`, `node_modules/` 가 섞이지 않았다
- [ ] 메시지에 **타입(feat/fix/...)** 을 붙였다
- [ ] 메시지만 읽고도 무엇을 했는지 알 수 있다
