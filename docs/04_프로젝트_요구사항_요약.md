## 1. 서비스 한 줄 정의

> 사용자가 **서울의 문화행사**를 날짜나 분야로 찾고, 관심 행사를 선택하면
> 그 행사를 **기준점**으로 주변 맛집·관광지·숙박을 묶어 **하루 여행 일정**을 추천하는 서비스

### 일반 여행 추천 서비스와 다른 점

| 일반 서비스 | 우리 서비스 |
|---|---|
| 관광지를 먼저 고름 | **문화행사를 먼저 고름** |
| 장소 중심 동선 | **행사 시간에 맞춘** 동선 (행사 시각 고정) |

## 2. 우선순위 구분

엑셀의 `우선순위` 열 기준입니다.

| 표시 | 의미 | 개발 순서 |
|---|---|---|
| 🟡 **우선 구현** | 이번 프로젝트에 **반드시** 들어가야 함 | 1순위 |
| ⚪ 다음 구현 | 여유가 되면 넣음 | 2순위 |
| 🟢 확장 후보 | 나중에 필요하면 검토 | 3순위 |
| 🔵 범위 협의 | 팀 회의로 포함 여부 결정 | 논의 필요 |

> 엑셀 `요구사항명` 칸의 **노란 배경 = 꼭 필요한 항목**, **초록 배경 = 나중에 넣을 항목**입니다.

## 5. DB 테이블 (초안)

> 상세 정의는 엑셀 `DB 테이블 정의` 시트, SQL은 [`database/schema/`](../database/schema/) 참고

| 테이블 | 역할 | 주요 컬럼 |
|---|---|---|
| `member` | 회원 | `member_id`(PK), `email`(UQ), `password`(BCrypt 해시), `nickname`, `created_at` |
| `trip_plan` | 저장된 일정 | `plan_id`(PK), `member_id`(FK), `title`, `area_code`, `start_date`, `end_date`, `headcount` |
| `plan_item` | 일정 속 개별 장소 | `plan_item_id`(PK), `plan_id`(FK), `content_id`(FK), `day_number`, `visit_order`, `visit_time`, `ai_reason` |
| `place` | 장소·행사 정보 | `content_id`(PK), `content_type_id`(12=관광지/32=숙박/39=음식점), `title`, `addr`, `mapx`, `mapy`, `overview`, `image`, `collected_at` |

> 즐겨찾기(FAV-01) 테이블은 아직 정의서에 없습니다. **팀 논의 후 추가**가 필요합니다.
> (예: `favorite(member_id, content_id, created_at)` — 회원+장소 조합 유니크)

## 6. 개발 시 꼭 지킬 원칙

1. **없는 정보를 지어내지 않는다** — 요금·운영시간이 없으면 "정보 없음"으로 표시
2. **직선거리 ≠ 실제 이동시간** — 혼동되지 않게 표시
3. **본인 데이터만 수정 가능** — 남의 일정 조회·수정·삭제 차단 (SEC-01)
4. **비밀번호는 해시로 저장** — 평문 저장 절대 금지
5. **추천 생성만으로 저장되지 않는다** — 저장 버튼을 눌러야 저장 (PLAN-04)
6. **조건을 사용자 동의 없이 자동 완화하지 않는다** (UX-01)
