## 2. DB 만들기

### 2-1. 테이블

**처음 만드는 경우** — 통합 DDL **한 파일만** 실행합니다 (프로젝트 루트에서, `tripai` DB까지 만들어 줍니다).

```bash
mysql -u root -p < database/schema/01_TripAI_최종_DDL_v3.2.5.sql
```

> ⚠️ 통합본에는 02~05 변경이 이미 들어 있습니다. 이어서 02~05를 실행하면 컬럼 중복 오류가 납니다.

**예전 `01_tripai_ddl_v3.2.1.sql`로 만든 DB를 쓰는 경우** — 통합본은 실행하지 말고, 빠진 마이그레이션만 확인해서 실행합니다.

```sql
USE tripai;
SHOW COLUMNS FROM place LIKE 'cuisine_type';        -- 없으면 02 실행
SHOW COLUMNS FROM trip_plan LIKE 'food_preference';  -- 없으면 03 실행
SHOW COLUMNS FROM trip_plan LIKE 'cafe_yn';          -- 없으면 04 실행
SHOW COLUMNS FROM trip_plan LIKE 'search_dates';     -- 없으면 05 실행
```

```bash
mysql -u root -p tripai < database/schema/02_place_food_category_v3.2.2.sql   # 없는 것만
mysql -u root -p tripai < database/schema/03_trip_plan_food_condition_v3.2.3.sql
mysql -u root -p tripai < database/schema/04_trip_plan_meal_food_cafe_v3.2.4.sql
mysql -u root -p tripai < database/schema/05_trip_plan_event_condition_v3.2.5.sql
```

`03`~`05`가 빠져 있으면 일정 만들기·조건 수정·다시 추천이 오류가 납니다. 자세한 내용은 `database/schema/README.md`를 보세요.

## 3. 키 발급

| 키 | 꼭 필요? | 없으면 | 넣는 곳 |
|---|---|---|---|
| 서울시 문화행사 인증키 | **필수** | 행사가 하나도 없음 | `backend/.env` `SEOUL_CULTURE_API_KEY` |
| 카카오맵 JavaScript 키 | 권장 | 동선 지도가 개념도로 표시 (#87 병합 후) | `frontend/.env` `VITE_KAKAO_MAP_KEY` |
| OpenAI API 키 | 선택 | 규칙 기반 추천으로 동작 | `backend/.env` `OPENAI_API_KEY` |
| TourAPI 인증키 | 선택 | 음식점을 **다시 수집할 때만** 필요 (시드로 충분) | `backend/.env` `TOUR_API_SERVICE_KEY` |
| JWT 비밀값 | **필수** | 서버가 켜지지 않음 | `backend/.env` `JWT_SECRET` (직접 만든 아무 긴 문자열) |

### 3-1. 서울시 문화행사 인증키 (필수)

1. https://data.seoul.go.kr 로그인(회원가입)
2. 검색창에 **"서울시 문화행사 정보"** → 데이터셋 선택 (서비스명 `culturalEventInfo`)
3. **Open API** 탭 → **인증키 신청** → 사용 목적(예: 교육용 프로젝트) 입력 → 일반 인증키 발급
4. 마이페이지 > 인증키 관리에서 키 복사
5. 브라우저로 확인 (키 자리에 붙여 넣기):
   `http://openapi.seoul.go.kr:8088/발급받은키/json/culturalEventInfo/1/5/`
   → `"CODE": "INFO-000"`이 보이면 정상

### 3-2. 카카오맵 JavaScript 키 (권장)

각자 발급합니다(5분 정도). JavaScript 키는 등록한 도메인에서만 동작하지만, 그래도 GitHub·단체방에는 올리지 않습니다.

1. https://developers.kakao.com 로그인 → **앱** → **애플리케이션 추가하기** (앱 이름 `TripAI`, 카테고리 여행)
2. **앱 키(플랫폼 키)** 화면에서 **JavaScript 키** 복사
   - ⚠️ REST API 키·Admin 키가 아닙니다. Admin 키는 절대 프론트에 넣지 않습니다.
3. **JavaScript SDK 도메인**(또는 플랫폼 → Web → 사이트 도메인)에 `http://localhost:5173` 등록 — `https` 아님, 끝에 `/` 없음
4. **제품 설정**에서 **카카오맵 사용 설정 ON** (최근 만든 앱은 켜야 지도가 나옵니다)

### 3-3. OpenAI API 키 (선택)

- https://platform.openai.com/api-keys → **Create new secret key**
- 비워 두면 AI 없이 규칙 기반으로 일정을 만듭니다. 기능 확인에는 없어도 됩니다.

### 3-4. TourAPI 인증키 (선택 — 음식점 재수집할 때만)

1. https://www.data.go.kr 로그인 → **"한국관광공사_국문 관광정보 서비스_GW"** 검색 → 활용신청
2. 마이페이지 > 개발계정 > 해당 API → **일반 인증키(Decoding)** 복사
3. 수집 방법은 [08_TourAPI_음식점_수집.md](08_TourAPI_음식점_수집.md) (하루 호출 한도 1,000회)

## 4. .env 작성

`.env.example`을 복사해서 만듭니다.

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

### backend/.env

```properties
DB_URL=jdbc:mysql://localhost:3306/tripai?serverTimezone=Asia/Seoul&characterEncoding=UTF-8
DB_USERNAME=root
DB_PASSWORD=내DB비밀번호
SERVER_PORT=8080
JWT_SECRET=아무_긴_문자열_예시_tripai-local-secret-2026

SEOUL_CULTURE_API_KEY=서울시인증키
BATCH_EVENT_INITIAL_LOAD=false      # 5단계에서 처음 한 번만 true

OPENAI_API_KEY=                     # 선택
OPENAI_MODEL=gpt-4.1-mini
TOUR_API_SERVICE_KEY=               # 선택
```

- **한 줄에 `이름=값` 하나.** 키를 붙여 넣다가 줄이 바뀌면 서버가 `Malformed entry` 오류로 켜지지 않습니다.
- 값에 따옴표·앞뒤 공백을 넣지 않습니다.

### frontend/.env

```properties
VITE_API_BASE_URL=http://localhost:8080
VITE_USE_MOCK_API=false
VITE_USE_PLAN_MOCK_API=false
VITE_USE_EVENT_MOCK_API=false
VITE_KAKAO_MAP_KEY=카카오JavaScript키
```

> ❗ **목업 설정 세 개는 모두 `false`.** 하나라도 `true`면 일정이 서버에 저장되지 않고 내 여행에도 나오지 않습니다.
> `.env`를 바꾼 뒤에는 프론트 개발 서버를 **껐다 다시 켜야** 반영됩니다.

## 5. 행사 데이터 적재

1. `backend/.env`에서 `BATCH_EVENT_INITIAL_LOAD=true`
2. 백엔드 실행(6단계) → 로그에 `=== 행사 데이터 초기 적재 종료 ===`가 나올 때까지 기다립니다 (약 19,000건, 몇 분)
3. **다시 `BATCH_EVENT_INITIAL_LOAD=false`로 되돌립니다.** (켜 두면 서버를 켤 때마다 다시 수집합니다)
4. 확인: `SELECT COUNT(*) FROM event WHERE event_content_id LIKE 'SEOUL-%';` → 약 19,000

이후에는 매일 03:00에 자동으로 갱신됩니다(서버가 켜져 있을 때).

## 6. 실행

터미널 두 개를 엽니다.

```bash
# 터미널 1 — 백엔드 (반드시 backend 폴더에서 실행해야 .env를 읽습니다)
cd backend
./gradlew bootRun        # Windows: gradlew.bat bootRun
```

```bash
# 터미널 2 — 프론트
cd frontend
npm install              # 처음 한 번, 또는 package.json이 바뀌었을 때
npm run dev
```

브라우저에서 **http://localhost:5173** 을 엽니다.

- 백엔드는 `localhost:5173`에서 오는 요청만 허용합니다. 프론트 포트를 바꾸면 요청이 막힙니다.
- 8080 포트가 이미 쓰이고 있다는 오류가 나오면, 이미 켜진 백엔드를 끄고 다시 실행하세요.

## 8. 병합 전 PR 미리 보기

아직 `develop`에 들어가지 않은 PR까지 합쳐 보고 싶을 때만 사용합니다. **이 브랜치는 확인용이라 push하지 않습니다.**

```bash
git fetch origin
git switch -c preview/local origin/develop       # 확인용 로컬 브랜치
git fetch origin pull/87/head:pr-87              # 보고 싶은 PR 번호마다 반복
git merge --no-edit pr-87
```

다 봤으면 정리합니다.

```bash
git switch develop
git branch -D preview/local pr-87
```

## 9. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 일정을 저장했는데 내 여행에 안 나옴 | `frontend/.env` 목업 설정이 `true` | 세 개 모두 `false` 후 프론트 재실행 |
| 메인에 행사가 없음 / 오래된 행사만 나옴 | 행사 적재를 안 했거나 `SEOUL_CULTURE_API_KEY` 오류 | 5단계 다시, 키 확인 URL로 `INFO-000` 확인 |
| 서버가 `Malformed entry` 로 안 켜짐 | `.env`에 키가 두 줄로 나뉨 | 한 줄에 `이름=값` 하나로 |
| 서버가 `JWT_SECRET` 관련 오류로 안 켜짐 | `backend/.env`에 `JWT_SECRET` 없음 | 아무 긴 문자열로 채우기 |
| `Access denied for user` | `DB_USERNAME`/`DB_PASSWORD`가 실제 DB 계정과 다름 | DB 접속 정보 확인 |
| 일정 만들기·조건 수정에서 500 오류 | 예전 DB에 마이그레이션 03~05 누락 | 2-1의 확인 쿼리로 빠진 것 실행 |
| DDL 실행 중 `Duplicate column name` | 통합본 뒤에 02~05를 또 실행함 | 통합본만 실행하면 됨 (이미 반영됨) |
| 지도가 개념도(그림)로 나옴 | 카카오 키 없음·도메인 미등록·카카오맵 사용 OFF | 3-2 확인 후 프론트 재실행 |
| 화면에서 요청이 전부 실패(CORS) | 프론트가 5173이 아닌 포트에서 실행됨 | `npm run dev` 기본 포트(5173) 사용 |
